# 逐条理由（附录 GQ.4）：
#  1. zq_gemm_32f_align_c.c        —— 重复定义在一个 #define 宏块内部
#     （145/158/171 行是宏不是函数），自动区间会连带排掉 f32 需要的
#     zq_base_type / zq_mm_*，**故意没自动修**
#  2. zq_cnn_convolution_gemm_*    —— padK 在 NEON 分支里只有
#     `#if !__ARM_NEON_FP16 ... #endif`、**没有 #else**（x86 那侧是三档齐全的
#     #if/#elif/#else）。补 #else 能编过但 padK 的取值只能猜 ——
#     宁可保留一个响亮的编译失败，也不换成可能静默算错。**故意没修**
#  3. zq_cnn_deconvolution_gemm_*  —— 同上的 padK（附录 H9 那一族）
#  4. zq_cnn_depthwise_convolution  —— unknown type，见基线里的 error 原文
#  5. zq_cnn_scalaroperation        —— 语法错误，见基线里的 error 原文
#  6. zq_cnn_convolution            —— **桩的限制**，不是代码缺陷：
#     arm_neon.h 里 `ZQA_NEON_STUB_ANY` 展开成 `((void)sizeof(...), 0)`，
#     当代码把内在函数的结果当可调用对象用时报这一条
