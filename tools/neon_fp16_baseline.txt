# 这一档对应 `SIMD_ARCH_TYPE=arm64-fp16`（根 CMakeLists.txt:95 真实实现，
# build-with-cmake.md 里没有文档）。2026-10-04 之前它**从未被任何编译器看过**。
#
# 起点 23/36 编不过。其中 `float16_t`（45 个文件用到、全仓从未定义）
# 已修（ZQ_CNN_CompileConfig.h 里加了受控 typedef），降到 11。
#
# 剩下的 11 条分三类，**都不是自动修的**，理由如下。
#
# 1) 10 条 `redefinition of` —— 通用实现与 FP16 实现同时被编进来。
#    试过自动加 `#if !(__ARM_NEON && __ARM_NEON_FP16)` 守卫：**把 Windows
#    构建弄坏了**（LNK2019，zq_cnn_lstm_TF_32f_align0_general 等 3 个符号消失）。
#    根因：要包住的那几个区间里**有一个 #else** ——
#    `zq_cnn_lstm_32f_align_c.c:143` 的 #else 是第 37 行 `#if __ARM_NEON` 的
#    **非 NEON 分支**，x86 要用的代码就在里面，
#    而我插入的 #if/#endif 把整个非 NEON 分支吞掉了。
#    正确做法要逐个人读那段区间、按它的真实结构放守卫，
#    那是脚本替不了的判断。详见 audit_k3_20261001.md 附录 GQ.4。
#
# 2) 2 条 `padK undeclared` —— NEON 分支的内层 `#if !__ARM_NEON_FP16`
#    **没有 #else**（x86 那侧是三档齐全的 #if/#elif/#else）。
#    补 #else 能编过，但 padK 的取值只能猜，而本机无法在 ARM 上验证：
#    宁可保留响亮的编译失败，也不换成可能静默算错。
#
# 3) 个别文件是**桩的限制**（ZQA_NEON_STUB_ANY 展开成
#    `((void)sizeof(...), 0)`，代码把内在函数结果当可调用对象用时报的）。
