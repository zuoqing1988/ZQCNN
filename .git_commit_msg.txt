II.21：pnet 调试开关只关不恢复（且两条路径行为相反）

_Pnet_stage 单线程分支里：

    pnet[0].TurnOffShowDebugInfo();
    //pnet[0].TurnOnShowDebugInfo();      <- 恢复那一行被注释掉了，就挂在下一行
    _compute_Pnet_single_thread(input, maps, mapH, mapW);

两个问题叠在一起：
1. 只关不恢复：用户 TurnOnShowDebugInfo() 之后，第一次 Find 就把 pnet 的调试
   永久关掉，之后再也开不回来。
2. 两条路径行为相反：多线程分支根本没有 TurnOffShowDebugInfo()。
   于是 thread_num==1 时 pnet 不打、thread_num>1 时照打 —— 这不是取舍，是漏了。

根因是本类的 show_debug_info 和 pnet[i].show_debug_info 是两份从不互相通知的状态，
「该恢复成什么样」根本无从判断。

修法：
* TurnOnShowDebugInfo() / TurnOffShowDebugInfo() 现在同时传播给 pnet/rnet/onet/lnet
  （AspectRatio 没有 lnet 成员，只传播三个 —— 这是 -fsyntax-only 抓到的，
   第一版照抄了另外四份的写法，它多写了一行 lnet）。
* _Pnet_stage 里按本类的 show_debug_info 记下原值，跑完再恢复。

门禁加 A43（21 条规则）：pnet[0].TurnOffShowDebugInfo() 出现时必须同时有
TurnOnShowDebugInfo 恢复、有 const bool pnet_debug_was 存原值、
且 TurnOnShowDebugInfo 里有 pnet[i]. 传播。三条缺一即报错。变异测试去掉恢复行立刻被抓。

A/B 对拍这次**故意**有差异，而且这正是修复生效的证据：
  SampleMTCNN 97 行 / _NCHWC4 28 行 / _Interface 265 行 / LoadFromCode 1128 行
所有变化行都是新增的层级调试行（Conv layer: / DwConv layer: / BatchNorm layer: /
PReLU layer: / Innerproduct layer: ...），**没有一行是删减**。
把层级调试行过滤掉之后，四个 sample 的检测结果与阶段计数**逐字节相同**。

也就是说 SampleMTCNNLoadFromCode.cpp:123 那个 mtcnn.TurnOnShowDebugInfo() **以前是白调的**
—— 它让 MTCNN 自己开始打阶段计时，但 pnet 那 800 多行层级调试在第一次 Find 之后
被永久吞掉了。现在恢复了。

注意：tools/capture_sample_outputs.sh 的 NORM 正则不覆盖层级调试行
（只归一化 <T>ms / <GF>GF/s 那几个数字），所以 ab_diff_sample_outputs.sh 对
SampleMTCNNLoadFromCode 的 A/B 会看到这上千行。行数差异是预期的，做 A/B 时别当成数值回归。

实测：自测 22/22、普查 5 文件全过；变异测试 A43 变红；Linux -fsyntax-only RC=0；
Windows 四个 sample RC=0；WSL make 无 error。
